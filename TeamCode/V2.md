# V2 TeleOp

**Competition setup: AutoPath (Autonomous group) + BioBuzz Blue/Red TeleOp V2.** AutoPath V2 was
retired on 2026-11-12; AutoPath itself now pre-aims the turret from odometry (see
[AUTONOMOUS.md](AUTONOMOUS.md)). The original **BioBuzz Blue/Red TeleOp** stays for comparison.

| Driver Station entry | Group | What it is |
| --- | --- | --- |
| BioBuzz Blue TeleOp V2 / BioBuzz Red TeleOp V2 | Competition | V2 TeleOp (original one-person controls) |
| Turret Scale Check V2 | Test | Measures turret ticks per degree |

Code lives in `TeamCode/src/main/java/org/firstinspires/ftc/teamcode/v2/`.

## What changed

| Area | Original | V2 |
| --- | --- | --- |
| HIVE target | Averages every alliance tag (both CELLS if both are visible) | Aims at the **upward CELL's** 4-tag cluster only; distance from that cluster |
| Turret goal | Camera bearing; between frames only chassis **rotation** is corrected | Remembers the target's **field position**; odometry keeps it aimed while strafing, spinning or when the tag drops out |
| Turret power | 0.22 cap includes feedforward (saturates at ~177 deg/s chassis spin) | 0.22 cap on the P/D correction only; spin/strafe feedforward added on top (total 0.6) |
| Turret jitter | Raw target changes and full friction kick near aim | Small camera changes filtered over 100 ms; reduced friction kick near target; encoder-rate noise cannot wake a settled turret |
| Shooter F | Fixed 13.83 | Reference F x 13.3 V / battery voltage, refreshed every 0.5 s (same scale as the tuner) |
| Shot distance (TeleOp) | Raw frame; 3215 RPM the moment a tag blinks | Median of 5 frames, held 1 s, then odometry range, then 3215 |
| "At speed" | +/-100 RPM (as wide as the whole table) | TeleOp: +/-10 RPM, stable for 150 ms for ready indication; Auto retains +/-50 RPM |
| TeleOp shooting | X toggles the gate, RT feeds inward | Same original one-person controls: A shooter, X gate, RT/LT intake |
| Gate unloading | Auto only | Also TeleOp when X opens the gate |
| Loop speed | AUTO bulk caching, color + distance I2C reads, telemetry every loop | MANUAL bulk caching, distance-only read, telemetry every 100 ms; loop time shown |

Shared code touched (no behavior change for the original TeleOp): `Robot.setTurretPower` is now
public with a few read-only getters; `BioBuzzAutoMechanisms.Hardware` has an optional
`burstFinishedEarly` hook that AutoPath's adapter never uses. The drive-only legacy
**BioBuzz Auto** moved from the Competition group to Development. V2 TeleOp starts by holding
the turret's field direction until it first sees a tag (there is no Auto-to-TeleOp handoff).

## V2 TeleOp controls

V2 TeleOp is testing **P=180, I=0, D=0, reference F=12.71 at 13.3 V** (P was 90 until 2026-11-12).
Both Blue and Red entries use this tune; telemetry shows it under `Shooter tune`.
The constants live in `Robot.java` as `V2_TELEOP_SHOOTER_P` / `V2_TELEOP_SHOOTER_F`, and
Flywheel Tuning starts from the same reference F. Original OpModes and AutoPath keep
`SHOOTER_P` / `SHOOTER_F`, and the distance table remains 3215, 3220, 3235 RPM.
See [SHOOTER_TUNING.md](SHOOTER_TUNING.md) for the P comparison test.

Both **BioBuzz Blue TeleOp V2** and **BioBuzz Red TeleOp V2** now use the original
one-person layout entirely on **gamepad 1**. After AutoPath, select the matching V2 TeleOp.

| Gamepad 1 | Action |
| --- | --- |
| Left stick | Drive / strafe |
| Right stick X | Rotate chassis |
| LB (hold) | Slow drive (40%); no logging action |
| RT (hold) | Intake / feed inward while held; does not turn the shooter on or open the gate |
| LT (hold) | Intake outward while held (RT wins if both are held) |
| A | Shooter on/off |
| X | Shooting toggle: first press opens the gate, runs the intake inward and turns the LED purple (only with the shooter on and within +/-50 RPM of target); second press closes the gate and stops the intake |
| Y | Auto-aim on/off |
| B (hold) | Center turret |
| D-pad left/right (hold) | Jog turret at -0.375 / +0.375 power; auto-aim resumes on release |
| D-pad up/down | RPM trim +/-10 per press; hold LB for +/-1 |
| RB | Flower toggle: **OFF=0.14 / ON=0.505**, shared with original TeleOp and Auto |
| Back during INIT | Zero turret while physically pointing forward |
| Back after START | Clear RPM trim only (never re-zero the turret) |
| Left stick click | Enter/exit calibration: freeze/unfreeze the table's base RPM |
| Right stick click | In calibration, log the visible tag's distance and commanded RPM |

Gamepad 1 rumbles when the robot becomes ready to shoot. Gamepad 2 is unused. RT/LT are
reserved for intake, so hold-to-shoot and force-shoot are not bound in this layout.
D-pad left/right jog the turret rather than adjusting aim trim.

For calibration, park at a shooting spot, click the left stick, and adjust with D-pad up/down.
The table's base RPM stays fixed even if measured distance jitters; manual trim still works.
LB remains slow drive and also selects 1-RPM trim. Back clears trim without exiting calibration.
Click the left stick again to resume live distance lookup, retaining trim. Restart clears the
trim and calibration mode. The PIDF is P=180, I=D=0, reference F=12.71 at 13.3 V.

`Speed stable` means measured RPM stayed within +/-10 of the command for 150 ms, with no
sample gap longer than 150 ms. Each trim edit restarts that interval. READY/rumble also requires
aim and a calibrated gate. This is an indication, not a promise of physical accuracy: sensor
noise can prevent it from staying ready, and a ball naturally drops flywheel speed. X/RT
remain manual and can feed outside the band. Auto's readiness window is unchanged.

Small camera changes are smoothed in field coordinates, leaving chassis rotation/translation
compensation immediate. Changes of at least 3 degrees bypass the filter once two frames in a
row agree (about 30 ms), so a single bad frame, such as half a tag cluster blinking out, is
ignored. The first sighting and reacquisition after a dropout are taken immediately. This
targets jitter seen in the first TeleOp test; it still needs an on-robot comparison. The
knobs are `FieldAimV2.VISION_SMOOTHING_MS`, `VISION_SNAP_DEG`, `VISION_SNAP_CONFIRM_FRAMES`
and `STATIC_RAMP_DEG`.

## Before trusting V2: setup checks

1. **Up-CELL direction.** Stand where the camera sees both CELLS' tag clusters. The `HIVE cell`
   line must name the CELL that is physically up (and show both `ty` values). If it picks the
   down CELL, set `HiveTargetV2.UP_CELL_TY_SIGN = -1` (camera image upside down). If you never
   see both clusters at once, this does not matter.
2. **Turret scale.** Run **Turret Scale Check V2** (instructions on screen and in the file). The
   code uses 2.8212 ticks/deg; an old hand measurement said ~3.02. Odometry aiming depends on it.
3. **Feedforward reference.** The tuner and V2 share `Robot.SHOOTER_F_REFERENCE_VOLTS` (13.3 V).
   Keep this fixed while tuning; copy reference F, not voltage-scaled applied F. See
   [Shooter tuning](SHOOTER_TUNING.md) for controls, burst tests and distance calibration.
4. **Optional geometry.** `FieldAimV2.TURRET_OFFSET_FORWARD_IN / LEFT_IN` (turret axis vs chassis
   center) and `RobotV2.TAG_HEIGHT_ABOVE_CAMERA_IN` make odometry aiming slightly more exact.

## Building a long-range shot table

The measured RPM table only covers 1.39-1.62 m and clamps at 3235 RPM beyond that. To extend it:
at each distance you shoot from, click the left stick to freeze the base RPM and trim until
shots score. D-pad up/down changes 10 RPM; LB + up/down changes 1 RPM. Click the right stick
with a HIVE tag visible to append distance, commanded/measured RPM, voltage and pose to
`/sdcard/FIRST/biobuzz_shot_table.csv`. A telemetry message confirms the saved point. Add points to
`SHOOTER_DISTANCE_METERS / RPM` in `Robot.java` (both versions use that table).
Logging points does not automatically change the distance table.

## Comparing old vs new

Same battery charge, same spots, at least 3 runs each:

- **Stationary shots:** 12 shots each from near, mid and far; count makes.
- **Lock while moving:** strafe sideways past the HIVE and spin in place; watch whether the
  turret stays on the CELL (V2 should; the original drifts during strafing).
- **Loop time:** V2 shows it; the original does not.

## Tests

```sh
python3 TeamCode/tests/run_v2.py
```

Compiles all TeamCode (original + V2) against the cached SDK and Pedro libraries and runs the
hardware-free V2 checks (HIVE CELL choice, field-anchored aim, latency, feedforward, limits,
distance filter, gate sequencing, one-person input isolation, flower ON/OFF commands, jitter
rejection, voltage compensation, early burst end).
They do not prove on-robot behavior; that needs the comparison above.
