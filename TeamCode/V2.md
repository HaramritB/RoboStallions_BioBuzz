# V2 TeleOp and Auto

V2 is a separate set of OpModes, so you can run old and new back to back on the same robot.
The original **BioBuzz Blue/Red TeleOp** and **AutoPath** behave exactly as before.

| Driver Station entry | Group | What it is |
| --- | --- | --- |
| BioBuzz Blue TeleOp V2 / BioBuzz Red TeleOp V2 | Competition | V2 TeleOp (original one-person controls) |
| AutoPath V2 Blue / AutoPath V2 Red | Autonomous | V2 Auto (preselects the matching V2 TeleOp) |
| Turret Scale Check V2 | Test | Measures turret ticks per degree |

Code lives in `TeamCode/src/main/java/org/firstinspires/ftc/teamcode/v2/`.

## What changed

| Area | Original | V2 |
| --- | --- | --- |
| HIVE target | Averages every alliance tag (both CELLS if both are visible) | Aims at the **upward CELL's** 4-tag cluster only; distance from that cluster |
| Turret goal | Camera bearing; between frames only chassis **rotation** is corrected | Remembers the target's **field position**; odometry keeps it aimed while strafing, spinning or when the tag drops out |
| Turret power | 0.22 cap includes feedforward (saturates at ~177 deg/s chassis spin) | 0.22 cap on the P/D correction only; spin/strafe feedforward added on top (total 0.6) |
| Turret jitter | Raw target changes and full friction kick near aim | Small camera changes filtered over 100 ms; reduced friction kick near target; encoder-rate noise cannot wake a settled turret |
| Auto turret | Sweeps for the tag at each shooting spot | Pre-aims at the HIVE from odometry; only sweeps if nothing is seen within 1.5 s |
| Shooter F | Fixed 13.83 | 13.83 x 12.5 V / battery voltage, refreshed every 0.5 s |
| Shot distance (TeleOp) | Raw frame; 3150 RPM the moment a tag blinks | Median of 5 frames, held 1 s, then odometry range, then 3150 |
| "At speed" | +/-100 RPM (as wide as the whole table) | +/-50 RPM, stable for 150 ms |
| TeleOp shooting | X toggles the gate, RT feeds inward | Same original one-person controls: A shooter, X gate, RT/LT intake |
| Gate unloading | Auto only | Also TeleOp when X opens the gate |
| Red Auto | Not supported (blue poses only) | Blue route mirrored (untested on a field) |
| Auto timing | Fixed 4 s stop at spot 2; 2 s burst; 0.3 + 0.3 s readiness | No fixed stop; burst ends when all 4 balls are seen leaving; 0.2 + 0.15 s readiness |
| Loop speed | AUTO bulk caching, color + distance I2C reads, telemetry every loop | MANUAL bulk caching, distance-only read, telemetry every 100 ms; loop time shown |
| Auto to TeleOp | Nothing carried over | Pose + HIVE target handed over if the Pinpoint still matches |

Shared code touched (no behavior change for the originals): `Robot.setTurretPower` is now public
with a few read-only getters; `BioBuzzAutoMechanisms.Hardware` has an optional
`burstFinishedEarly` hook that the original adapter never uses. The drive-only legacy
**BioBuzz Auto** moved from the Competition group to Development.

## V2 TeleOp controls

Both **BioBuzz Blue TeleOp V2** and **BioBuzz Red TeleOp V2** now use the original
one-person layout entirely on **gamepad 1**. V2 Auto still preselects those same entries.

| Gamepad 1 | Action |
| --- | --- |
| Left stick | Drive / strafe |
| Right stick X | Rotate chassis |
| LB (hold) | Slow drive (40%); no logging action |
| RT (hold) | Intake / feed inward; does not turn the shooter on or open the gate |
| LT (hold) | Intake / feed outward |
| A | Shooter on/off |
| X | Manual gate toggle, independent of aim and shooter speed |
| Y | Auto-aim on/off |
| B (hold) | Center turret |
| D-pad left/right (hold) | Jog turret at -0.15 / +0.15 power; auto-aim resumes on release |
| D-pad up/down | RPM trim +/-50 per press |
| RB | Flower toggle: **OFF=0 / ON=0.18**, shared with original TeleOp and Auto |
| Back during INIT | Zero turret while physically pointing forward; disabled after START |

Gamepad 1 rumbles when the robot becomes ready to shoot. Gamepad 2 is unused. RT/LT are
reserved for intake, so hold-to-shoot and force-shoot are not bound in this layout.
D-pad left/right jog the turret rather than adjusting aim trim.

Small camera changes are smoothed in field coordinates, leaving chassis rotation/translation
compensation immediate. Changes of at least 3 degrees, the first sighting and reacquisition
following a dropout bypass the filter. This targets jitter seen in the first TeleOp test;
it still needs an on-robot comparison.

## Before trusting V2: setup checks

1. **Up-CELL direction.** Stand where the camera sees both CELLS' tag clusters. The `HIVE cell`
   line must name the CELL that is physically up (and show both `ty` values). If it picks the
   down CELL, set `HiveTargetV2.UP_CELL_TY_SIGN = -1` (camera image upside down). If you never
   see both clusters at once, this does not matter.
2. **Turret scale.** Run **Turret Scale Check V2** (instructions on screen and in the file). The
   code uses 2.8212 ticks/deg; an old hand measurement said ~3.02. Odometry aiming depends on it.
3. **Nominal voltage.** `RobotV2.NOMINAL_VOLTAGE` (12.5) should be the battery voltage when the
   shooter F was tuned. The burst logger CSVs record `battery_v`.
4. **Optional geometry.** `FieldAimV2.TURRET_OFFSET_FORWARD_IN / LEFT_IN` (turret axis vs chassis
   center) and `RobotV2.TAG_HEIGHT_ABOVE_CAMERA_IN` make odometry aiming slightly more exact.
5. **Red Auto.** The red route is the blue route mirrored across the field center line
   (`FieldMirrorV2.MODE`). Walk through it slowly the first time. If the field is rotationally
   symmetric instead, set `MODE = ROTATE_180`. On path 5 (an exact 180 deg turn) Pedro turns the
   same way on red as on blue rather than the mirror image; the route still ends the same.

## Building a long-range shot table

The measured RPM table only covers 1.41-1.90 m and clamps at 3250 RPM beyond that. To extend it:
at each distance you shoot from, trim RPM with D-pad up/down until shots score. Record the
`Shot distance`, commanded RPM and battery voltage shown in telemetry. Add those points to
`SHOOTER_DISTANCE_METERS / RPM` in `Robot.java` (both versions use that table).
The earlier gamepad 2 LB shot-table shortcut is removed from V2 TeleOp because LB is slow
mode in the original one-person layout.

## Comparing old vs new

Same battery charge, same spots, at least 3 runs each:

- **Auto:** total time, balls scored per volley, and whether the turret had to sweep (telemetry
  shows `SEARCH`). Run AutoPath and AutoPath V2 Blue.
- **Stationary shots:** 12 shots each from near, mid and far; count makes.
- **Lock while moving:** strafe sideways past the HIVE and spin in place; watch whether the
  turret stays on the CELL (V2 should; the original drifts during strafing).
- **Loop time:** V2 shows it; the original does not.

## Tests

```sh
python3 TeamCode/tests/run_v2.py
```

Compiles all TeamCode (original + V2) against the cached SDK and Pedro libraries and runs the
hardware-free V2 checks (HIVE CELL choice, field-anchored aim, latency, feedforward, limits,
distance filter, gate sequencing, one-person input isolation, flower ON/OFF commands, jitter
rejection, mirroring, voltage compensation, early burst end).
They do not prove on-robot behavior; that needs the comparison above.
